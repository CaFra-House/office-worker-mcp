# Docker Deployment Guide — `office-worker-mcp`

The official Docker image packages all 30 document processing tools into a self-contained container with zero host dependencies. It is the recommended deployment method for Windows (no WSL2 required), macOS, and Linux.

- **Image:** `ghcr.io/cafra-house/office-worker-mcp:latest`
- **Architectures:** `linux/amd64`, `linux/arm64` (multi-arch native)
- **Base image:** `python:3.12-slim` (Debian 12 Bookworm)
- **User:** Non-root (`appuser`, UID 10001)
- **Working Directory:** `/data` (pre-configured volume)

---

## Why use the Docker image?

Office Worker integrates several external system engines to provide comprehensive document fidelity:
- **LibreOffice Headless** (`writer-nogui`, `calc-nogui`, `impress-nogui`) for native `.docx`, `.xlsx`, and `.pptx` conversion to PDF.
- **Tesseract OCR v5** (`tesseract-ocr` + `tesseract-ocr-spa`) for optical character recognition on scanned PDFs and images.
- **WeasyPrint C libraries** (`libpango-1.0-0`, `libpangocairo-1.0-0`, `libgdk-pixbuf-2.0-0`, `shared-mime-info`) for HTML/CSS to PDF rendering (`design_mode="premium"`).
- **Poppler utilities** (`pdftoppm`) for PDF page rasterization previews.
- **Full extras included:** `[sign]` (cryptographic PAdES signature via PyHanko), `[book]` (EPUB export via EBookLib), `[ocr]` (PyTesseract + Pillow) and `[pptx]` (html-to-pptx; native chart rendering falls back gracefully without Chromium).

With Docker, you do not need to install compilers, C shared libraries, or LibreOffice on your host system.

## Agent Configuration (stdio)

AI agents connect to Office Worker over standard I/O (stdio). The container is invoked directly by the agent runtime using `docker run -i --rm`.

### 1. Claude Desktop

Edit your configuration file:
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
- **Linux:** `~/.config/Claude/claude_desktop_config.json`

```json
{
  "mcpServers": {
    "office-worker": {
      "command": "docker",
      "args": [
        "run",
        "-i",
        "--rm",
        "-v",
        "/absolute/path/to/your/documents:/data",
        "ghcr.io/cafra-house/office-worker-mcp:latest"
      ]
    }
  }
}
```

> **Windows note:** In Windows paths, use forward slashes or escaped backslashes, e.g. `"C:/Users/username/Documents:/data"`.

### 2. Cursor IDE

In Cursor Settings (`Features` → `MCP Servers` → `Add New MCP Server`) or in `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "office-worker": {
      "command": "docker",
      "args": [
        "run",
        "-i",
        "--rm",
        "-v",
        "${workspaceFolder}:/data",
        "ghcr.io/cafra-house/office-worker-mcp:latest"
      ]
    }
  }
}
```

`${workspaceFolder}` automatically mounts your current project directory into the container's `/data`.

### 3. Hermes Agent / Generic MCP Client

In your Hermes agent configuration (e.g., `config.yaml` or `mcp_servers.json`):

```json
{
  "office-worker": {
    "command": "docker",
    "args": [
      "run",
      "-i",
      "--rm",
      "-v",
      "/home/user/workspace/docs:/data",
      "ghcr.io/cafra-house/office-worker-mcp:latest"
    ]
  }
}
```

## Output Files & Volume Mounting

- The container sets `WORKDIR /data`.
- Any relative file path generated by tools (e.g., `"output": "report.pdf"`) will be written to `/data/report.pdf`, immediately appearing in the mounted folder on your host machine.
- Container runs as non-root `appuser` (UID 10001) with write permissions in `/data` and `HOME=/tmp`.

## Running CLI Diagnostics (`owi`)

You can execute the built-in CLI (`owi`) directly inside the container without running the MCP server:

### Run Doctor (Environment Audit)
```bash
docker run --rm --entrypoint owi ghcr.io/cafra-house/office-worker-mcp:latest doctor
```

Output:
```json
{
  "status": "ok",
  "os": "linux",
  "package_manager": "apt",
  "core_ready": true,
  "all_ready": true,
  "capabilities": { ... }
}
```

### Install packaged skills to a local directory
```bash
docker run --rm -v $(pwd):/data --entrypoint owi ghcr.io/cafra-house/office-worker-mcp:latest skill install docx-pro --dest /data/skills
```

## Multi-Architecture (AMD64 & ARM64)

The GitHub Actions workflow compiles native multi-platform container images:
- `linux/amd64` (Standard x86_64 servers, Intel/AMD desktops)
- `linux/arm64` (Apple Silicon M-series, Raspberry Pi 4/5, AWS Graviton, Oracle ARM)

Docker will automatically pull the native architecture matching your host machine. No manual platform flag is required.
